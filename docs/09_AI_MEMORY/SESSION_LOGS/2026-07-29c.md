## Architectural Direction: Content Engine

This session established the unification pattern:

```
RichEditor (shared component)
    → TipTap JSON (storage format)
    → renderTipContent() (single renderer)
    → Public UI
```

**Approved next phase:** Content Engine consolidation under `content/` directory with:
1. Plugin-based `ContentNodeRegistry` (dispatcher pattern, not if/else)
2. Shared normalizer (`normalizeRichContent`) for TipTap JSON / plain text / legacy HTML
3. Per-plugin tests (editor + renderer + round-trip)
4. Format-agnostic API (`content.parse`, `content.render`, `content.normalize`)

See `CURRENT_STATE.md` and AGENTS.md for the phased implementation plan.

## Production Incident: Homepage TipTap JSON Leakage (post-release)

**Status:** RESOLVED  
**Severity:** Production presentation regression, no data loss.

**Root Cause:** `src/routes/index.tsx:222` rendered `{s.short_description}` directly. After the RichEditor was deployed for Services, the CMS saved `short_description` as TipTap JSON string. The homepage had no parsing logic.

**Fix:** Added `extractPlainText()` to `content-hooks.ts` — extracts text nodes from TipTap JSON. Applied to `index.tsx:222`.

**Data verification:** All 16 service short/long descriptions intact. About biography intact (5967 chars, 13 text nodes). Blog unaffected.

**Tests added:** 3 content-pipeline tests (extractPlainText compatibility matrix, all services pages, all info pages) + 1 homepage regression test. **24/24 tests pass.**

**Prevention:** `extractPlainText()` is now in shared lib. Regression test fails if raw TipTap keys appear on homepage. Audit confirmed no other direct renderings of rich-content fields.

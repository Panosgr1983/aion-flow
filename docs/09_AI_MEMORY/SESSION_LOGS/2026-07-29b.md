## Key Decisions

1. **Service FAQ designed tenant-agnostic.** Table has tenant_id FK, CMS tab is in core Services.tsx (not module-specific), helper in shared dataHelpers.ts, public hook follows useServiceBySlug pattern. Reusable by any tenant without code changes.

2. **Controlled sync save model.** `setFaq()` updates existing entries by index, inserts excess, deletes removed. Single atomic call — no partial saves, no orphan data.

3. **Single-query hook.** `useServiceFaq()` uses Supabase `services!inner` join instead of waterfall (service → FAQ). Solves SSR hydration timing issue — spinner renders during fetch, content after hydration.

4. **data-testid selector pattern** for repeated/translated/structurally fragile elements. Semantic locators for static headings. Standard documented in AGENTS.md.

5. **AKES v1.6 discipline protocols formalized** based on user feedback: Knowledge Hydration before any work, Decision History preservation, Source/Confidence Classification (✅🟡🔷❓), Memory Persistence as definition of done, Secure Credential Access three-tier architecture.

6. **Performance Baseline #1 classification.** All metrics schema defined but runtime wall-clock and tool-level capture not yet implemented — timestamps recorded as null with documented reason.
